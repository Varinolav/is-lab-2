# Уникальность названия фильма

Названия сравниваются в Java после strip() и toLowerCase(Locale.ROOT).
Регистр и пробелы по краям не учитываются; исходное написание сохраняется.
«Дюна», «ДЮНА» и « Дюна » считаются одним названием.

Ограничение действует для всех пользователей при создании, редактировании
и импорте. При редактировании текущий фильм исключается из проверки.
Импорт проверяет и существующие названия, и дубликаты внутри файла до
сохранения объектов. Конфликт возвращает HTTP 409 с русским сообщением;
импорт целиком откатывается и оставляет FAILED в истории.

Новых UNIQUE, индексов, триггеров и полей в БД нет. Репозиторий только читает
названия; сравнение выполняется в MovieNameService.

Параллельные операции записи названий сериализуются одним Semaphore.
Он освобождается через JTA afterCompletion после commit или rollback,
а не при возврате из метода сервиса. Это защищает текущую конфигурацию
с одним экземпляром приложения. Для нескольких экземпляров нужна общая
координация между ними.

Ручные проверки:

1. Создать фильм, затем повторить создание с другим регистром и пробелами:
   второй запрос получает 409.
2. Обновить фильм, сохранив собственное название: запрос проходит.
3. Изменить название на название другого фильма: 409, исходный фильм не меняется.
4. Импортировать файл с повторяющимися названиями: 409, новых объектов нет.
5. Импортировать файл с уже существующим названием: 409, новых объектов нет.
6. Одновременно создать одно название из двух пользовательских сессий:
   только один запрос получает 201, остальные — 409.

Повторная загрузка manual-tests/import/01-valid-three-movies.json теперь
возвращает 409, если названия уже заняты. Первый импорт свободных названий — 201.
Существующие записи автоматически не переименовываются и не удаляются.
